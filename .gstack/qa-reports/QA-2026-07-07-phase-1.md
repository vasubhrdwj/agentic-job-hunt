# QA — Phase 1 privacy and data ownership

Date: 2026-07-07
Branch: `v2-rebuild`
Phase: Privacy and data-ownership foundation
Verdict: PASS with known later-phase limitations

## What changed

- Added encrypted resume-bearing request storage with Fernet key rotation metadata.
- Added one-time run access tokens, stored server-side only as SHA-256 hashes.
- Required `Authorization: Bearer <access_token>` for run read, outcome write, and delete.
- Added no-store response headers for private API routes.
- Sanitized FastAPI validation errors so oversized/invalid resume input is not echoed.
- Added delete-run and retention cleanup paths.
- Disabled Google ADK/google-genai auto-instrumentation for user traffic.
- Kept draft text, prompt text, model responses, API keys, and auth tokens out of exported spans/logs by default.
- Restricted self-RAG retrieval to curated seed spans only until owner-scoped retrieval exists.
- Added provider consent and `/privacy` disclosure.
- Tightened provider prompts to bounded role-relevant resume excerpts only.
- Required explicit paid Gemini acknowledgement in production config.

## Known limitations left for later phases

- `POST /api/hunt` still blocks synchronously for the full hunt. Phase 2 moves this to a durable queue.
- SQLite remains a local/demo persistence layer. Phase 3 adds production persistence and web/worker topology.
- The run token is a temporary browser-session capability, not full user authentication. Phase 4 adds auth and abuse controls.
- Self-RAG now uses curated seed spans only. Owner-scoped learning from real users is deferred to Phase 4/5.
- Live source gate for at least 3 qualifying roles remains market-dependent and belongs to Phase 5.
